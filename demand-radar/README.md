# 觅需 · 设计师的需求雷达

面向国内中文市场、个人设计工作室的本地网页系统。优先验证景观概念、民宿/酒店方案、效果表达和定制视觉服务，兼顾绘画、摄影与阅读兴趣。

**第一版已实现需求研究与跟进工作台，不是自动获客或保证盈利的系统。** 默认数据库没有虚构的新闻、客户、订单或收入；五个预置服务方向均为“待验证假设”。

## 开始使用

需要 Python 3.12 或更新版本，无第三方运行依赖，也不需要购买 AI API。

1. 下载仓库 ZIP 并解压。
2. 打开 `demand-radar` 文件夹。
3. Windows 双击 `start-windows.bat`；Mac 在终端运行 `bash start-mac.command`。
4. 浏览器打开 `http://127.0.0.1:8765`。初次启动时若浏览器提示无法连接，等终端显示“需求雷达运行中”后刷新。
5. 保持终端开启；关闭终端会停止服务和自动采集。

也可用终端：

```sh
cd demand-radar
python3 radar.py serve
```

默认启动时采集一次，然后每小时采集一次；网页每分钟读取本地状态并提示新增数量。不是浏览器关闭后的系统通知，当前不发送微信或邮件。运行中的后台采集、网页提示和外部推送是三件不同的事。

```sh
# 调整采集间隔，单位秒，最少 300 秒
python3 radar.py serve --interval 3600
# 仅手动采集
python3 radar.py serve --no-auto-collect
# 单次采集，适合系统定时任务
python3 radar.py collect
# 单独持续采集，不启动网页
python3 radar.py watch --interval 3600
# 导出可读简报
python3 radar.py report > report.md
```

通常只运行 `serve` 即可，不必再运行 `watch`。单个进程内防止重复采集；多进程同时采集仍可能重复网络请求，数据库按标题去重。

## 日常怎么用

- **机会工作台**：看五个预置方向的近 30 天证据、服务边界、AI 提示词，记录报价、阶段、询价与实收。
- **需求证据库**：手动录入公开需求帖或经许可的访谈记录，保留原始链接与事实，支持搜索、筛选、删除。人工录入不是系统审核，标成“付费”也仍需你核实。
- **采集与运行**：管理公开 HTTPS RSS/Atom 来源，查看成功/失败时间，手动采集，导出 JSON 和研究简报。
- **本周行动指南**：先做 3 页原创案例，找目标客户确认范围和预算，再报价一个边界清晰的付费小样。

第一周建议优先测试：**民宿 / 小酒店景观概念与效果表达服务**。用绘画、摄影形成视觉特色，先验证客户是否愿意付费，再考虑将重复交付整理成模板或数字产品。

## 证据规则

| 类型 | 含义 | 基础分 |
|---|---|---|
| 资讯/热度 | 新闻、行业讨论、作品展示 | +2 |
| 具体痛点 | 用户明确表达问题，尚未委托 | +8 |
| 明确求购 | 明确寻找服务，记录原话、范围、预算等事实 | +18 |
| 付费证据 | 可核实的付费事实，避免录入隐私凭证 | +25 |

只计最近 30 天，最多 100 分。没有求购/付费时最多 25 分；这两类记录只有一个独立来源时最多 55 分。独立来源按链接网站或手动来源代号粗略归组，平台上的不同用户可能被保守地归为一个来源；同一用户跨平台也可能重复，需要人工核查。相同标题会被去重，可能将不同来源的同名帖子合并。这是透明、有限的优先级规则，不是市场规模、购买概率或盈利预测。

所有自动 RSS 条目均归为“资讯/热度”，不会自动把关键词或新闻当成委托。方向匹配为简单关键词，不是语义模型。若匹配不对，可删除后按正确方向重新录入。后续再根据你实际使用反馈增加分类编辑、自定义方向和经过评估的 AI 辅助。

## 来源与当前限制

预置两个 Bing 新闻 RSS 查询（庭院/民宿，设计/摄影/插画）。它们只帮助观察行业，不覆盖全网真实订单。可以添加更多合法可访问的公开 RSS/Atom，不采集登录后内容，不绕过平台限制。

**开发环境内对 Bing 等外站的请求遭到代理 403 拒绝。已确认失败会被记录并显示，但没有成功取得实时市场数据。** 采集器的解析、去重、错误处理通过测试；联网采集能否成功需要在允许该站访问的运行环境重新验证。你本机的网络也可能无法访问部分 RSS。

小红书、微信、闲鱼、猪八戒等不是已经接入的数据源。当前建议手动搜索、访谈并录入；接入自动数据源必须有公开接口或明确授权。需求帖中的“可公开查看”也不代表可以批量存储与营销。

系统默认使用标准 HTTPS 证书验证，并拒绝内网 RSS 地址及内网重定向。若环境依赖 HTTPS 代理且本地 DNS 不可用，则由已配置的可信代理解析公网域名；该代理必须限制内网目的地址。不要使用不可信代理。

## AI 如何参与

每个机会都有一份结合相关证据生成的可复制提示词：核实痛点、定义最小交付、规划验证、按工时与成本试算报价。可粘贴到已有 AI 工具，不会自动产生效果图或交付文件，也没有接入付费模型。

AI 可辅助概念发散、意向板、提案文案和拍摄计划；你负责场地事实、植物适生性、版权、尺寸和专业交付。概念咨询须与施工设计区分，报价前明确修改轮次、付款节点、授权和保密边界。

## 保存、备份与迁移

默认数据文件：`demand-radar/data/radar.sqlite3`，已加入 Git 忽略。它包含你的研究和业务记录，不上传 GitHub。JSON 是阅读/分析用导出，目前没有 JSON 回导功能。

备份：先停止 `serve` / `watch`，复制整个 `data` 文件夹到自己的安全位置。恢复：停止程序，用备份替换 `data` 文件夹，再重新启动。可用环境变量 `RADAR_DB` 指定其他数据库文件位置。多设备不会自动同步，收入差额只是已录实收减已录成本，不包含未录工时、税费等。

当前仅绑定本机地址，未提供登录、多用户权限、HTTPS 或公网部署。**不要直接暴露到公网。** 若要手机随时访问，下一步需要部署到具备身份验证和持久磁盘的服务，并配置获准的数据源；当前没有已发布的网址或 24 小时运行保障。

## 验证

```sh
python3 -m unittest discover -s tests -v
node --check static/app.js  # 可选，开发时检查前端语法
```

自动测试覆盖：空库假设、去重、证据等级、独立来源封顶、陈旧证据排除、RSS/Atom 解析、内网/危险链接、采集失败状态、HTTP 录入/删除/成交指标/导出及跨站写入拒绝。测试使用临时数据库，不污染个人数据。

浏览器交互另做了桌面和手机检查，包括录入、筛选、跟进保存、导出与删除。外部 RSS 成功连接仍未验证，不把模拟 feed 测试当作真实需求来源。
